# PDR: Чат с ИИ

Product Design Record — решение «что строим» до детальной спеки.

## Проблема

Пользователям нужен диалог с локальной LLM (`api-llm`) внутри того же мессенджера, без отдельного UI.

## Решение (одним абзацем)

Системный пользователь-бот; у каждого человека автоматически появляется 1:1-диалог с ним; сообщения пользователя уходят в `api-llm`, ответ сохраняется и доставляется как обычное сообщение.

## Скоуп

### In

- Системный User (email из env), seeder
- Автосоздание 1:1 с ботом при списке диалогов / регистрации
- Ответ бота на текстовые сообщения в этом диалоге через `POST {LLM_API_URL}/api/chat`
- Realtime/polling как у обычных сообщений
- Кнопка/пункт «Чат с ИИ» в UI нового чата

### Out

- Стриминг токенов в UI (можно позже)
- Группы с ботом, звонки с ботом
- Мультимодальность (картинки → LLM)
- Облачные LLM по умолчанию
- Админ-панель настроек модели

## Пользовательские потоки

1. Пользователь логинится → в списке диалогов есть «Ассистент» (или аналог).
2. Пишет текст → видит свой пузырь → через несколько секунд ответ бота.
3. Из «Новый чат» может явно открыть чат с ИИ (идемпотентно).

## Решения и компромиссы

| Вопрос | Решение | Почему |
|--------|---------|--------|
| Отдельная сущность Bot? | Обычный `User` | Минимальный дифф, reuse 1:1 |
| Sync vs afterResponse | Job после HTTP-ответа | LLM до ~минуты, не блокировать send |
| Stream в UI | Нет в v1 | Сложность; polling/WS хватает |
| История | Последние N сообщений диалога | Контекст без отдельного store |

## Риски

- `api-llm` / remote GPU недоступны → сообщение об ошибке в чате
- Долгий инференс → пользователь ждёт; UX терпим для учебного MVP
