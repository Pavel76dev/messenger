# PDR: Контекст ассистента по данным пользователя

Product Design Record — решение «что строим» до детальной спеки.

## Проблема

Чат с ИИ (012) видит только последние N текстовых сообщений **своего** 1:1-диалога.
Пользователь не может ставить широкие задачи вроде «суммируй переписку с X»,
«что в прикреплённом договоре», «по моим аудио-записям составь план» —
ассистент не имеет доступа к чатам, вложениям и транскриптам.

## Решение (одним абзацем)

Аудио-клипы **транскрибируются в фоне сразу при сохранении** (reuse ASR 014).
В чате с ботом перед ответом короткий **роутер-вызов LLM** решает, нужен ли
workspace-контекст по смыслу запроса; если да — Laravel собирает текстовый пакет
(переписки участника, извлечённый текст вложений, готовые транскрипты клипов)
с капами и делает второй вызов LLM с контекстом; если нет — ответ как в 012
(только история диалога с ассистентом).

## Скоуп

### In

- Авто-ASR: после `POST /api/audio-clips` (сохранение записи) — фон `pending` → Job/CLI 014 (без ожидания в HTTP)
- Ручной `POST .../transcribe` остаётся (повтор / error)
- Доступ ассистента только к данным **текущего** пользователя
- **Роутер:** LLM по тексту запроса (+ опц. краткий каталог источников) решает `need_workspace`
- Сборка workspace только при `need_workspace=true`: чаты, extract документов, транскрипты
- Извлечение текста из форматов вложений (Feature); кэш на attachment
- Обогащение `GenerateAiReply`: router → (optional context) → reply
- Лимиты объёма контекста; понятные ответы при пробелах в данных

### Out

- Векторный RAG / эмбеддинги
- Полноценный tool-calling / function calling api-llm (роутер — отдельный chat-вызов JSON, не tools API)
- Отправка бинарников/аудио в LLM
- OCR, zip-как-папка, записи LiveKit
- Чужие клипы / чужие диалоги
- UI выбора источников / ручной toggle «дать доступ к данным»
- Стриминг, смена модели в UI
- Синхронное ожидание ASR внутри ответа ассистента (транскрипты готовятся заранее)

## Пользовательские потоки

1. Пользователь сохраняет аудио в библиотеку → сразу фоновая транскрибация (UI library как в 014: pending → done/error).
2. Пишет ассистенту обычный вопрос («как дела?») → роутер: контекст не нужен → короткий ответ без workspace.
3. Пишет задачу по данным («суммируй чат с Бобом», «что я говорил в записях») → роутер: нужен контекст → сборка пакета → ответ с опорой на данные.
4. Если нужный клип ещё `pending`/`error` — бот опирается на готовое и честно отмечает пробел (не блокирует HTTP send).

## Решения и компромиссы

| Вопрос | Решение | Почему |
|--------|---------|--------|
| Когда ASR | При save клипа, в фоне | Транскрипты готовы к моменту задач ассистенту |
| Когда workspace | Роутер-LLM по запросу | Не раздувать каждый «привет» полным дампом |
| Как роутер | Отдельный `LlmClient::chat` → JSON `need_workspace` | Без tools API; api-llm уже умеет chat |
| RAG / tools | Нет в v1 | Проще отладка и деплой |
| Документы | Extract + кэш; в LLM текст | Не гонять байты |
| Группы | В пакет, если участник | «Все чаты» иначе неполны |

## Риски

- Ошибки роутера (false negative/positive) → калибровка prompt; при сомнении лучше `need_workspace=true`
- Контекст-окно при большом архиве → капы и приоритет недавнего
- PDF/DOCX extract неполный → статус error, без падения ответа
- Очередь ASR на много клипов подряд → pending в library; ассистент может увидеть «ещё нет текста»

## Открытые вопросы

_Нет блокирующих._ Согласовано с продуктом:

1. Контекст — **по решению ИИ (роутер)**, не всегда и не по ручному флагу.
2. ASR — **автоматически при сохранении** записи, в фоне.
