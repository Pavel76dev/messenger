# 017 — Контекст ассистента по данным пользователя

## Контекст

Фича 012 даёт чат с ИИ, но бот видит только историю своего 1:1. Вложения (006),
аудио-клипы и ASR (013/014) существуют отдельно. Нужен доступ ассистента к этим
данным **когда запрос этого требует**, плюс фоновая транскрибация всех сохранённых
записей. PDR: `017-assistant-workspace-context`, ADR-007.

## Цель

Пользователь ставит ассистенту задачи по перепискам, документам и аудио; система
сама решает (через LLM-роутер), нужен ли workspace-контекст. Транскрипты клипов
появляются в фоне сразу после сохранения записи — к моменту задач текст уже
обычно готов.

## User stories

- Как пользователь, я сохраняю аудио — и оно само уходит в транскрибацию в фоне.
- Как пользователь, я пишу ассистенту бытовой вопрос — он отвечает без прохода по всем моим чатам.
- Как пользователь, я прошу обработать переписку / документ / записи — ассистент подтягивает нужный текстовый контекст и опирается на него.
- Как пользователь, я понимаю, если часть файлов/транскриптов ещё не готова или не разобрана.

## Требования

### Must

#### Авто-транскрибация клипов

- [x] После успешного `POST /api/audio-clips` (сохранение) клип сразу `transcript_status=pending` (или эквивалент) и в фоне запускается существующий пайплайн ASR (014 Job/CLI) — HTTP ответа save не ждёт инференс
- [x] Ручной `POST /api/audio-clips/{id}/transcribe` сохраняется (повтор после error / перезапись по правилам 014)
- [x] Поведение UI library (pending → done/error) как в 014; отдельный обязательный клик «Транскрибировать» для нового клипа не требуется

#### Роутер контекста

- [x] В `GenerateAiReply` (afterResponse): **сначала** вызов LLM-роутера по тексту запроса пользователя (и краткой истории чата с ботом по желанию)
- [x] Роутер возвращает структурированно `need_workspace: true|false` (JSON; снять markdown-обёртку при необходимости)
- [x] При невозможности распарсить ответ роутера — считать `need_workspace=true` (безопаснее дать контекст)
- [x] При `need_workspace=false` — ответ как в 012: system prompt + история диалога с ботом, **без** полного workspace-пакета
- [x] При `need_workspace=true` — собрать workspace и второй вызов LLM (ответ пользователю) с контекстом + историей

#### Workspace-пакет (только если роутер сказал да)

- [x] В контекст только данные автора триггера:
  - сообщения из conversations, где он участник (direct + group), кроме диалога с ботом;
  - вложения: extracted text и/или метаданные;
  - свои `audio_clips`: `transcript_text` при `done`; при `pending`/`error`/`idle` — пометка в каталоге, без ожидания ASR в этом job
- [x] Извлечение текста вложений с кэшем (`extracted_text`, `extract_status` `idle|pending|done|error`, `extract_error`)
- [x] Форматы extract v1: `text/plain`, `text/markdown`, `text/csv`, `application/json`, `application/pdf`, docx (`application/vnd.openxmlformats-officedocument.wordprocessingml.document`); прочие — метаданные + «текст не извлечён»
- [x] Капы (config): max chars, лимиты сообщений/вложений/клипов; усечение с пометкой; приоритет более новым
- [x] ACL: чужие данные не попадают в пакет
- [x] Ошибки части источников не роняют ответ; бот может отметить пробелы
- [x] System prompt: при наличии workspace — опираться на него; не выдумывать отсутствующее
- [x] Люди↔люди чаты не вызывают LLM; HTTP send не блокируется на инференс/ASR/extract

### Should

- [x] Роутеру дать **краткий каталог** источников (названия диалогов, имена файлов, даты клипов без полных тел) — чтобы точнее решить `need_workspace`
- [x] Фоновый extract вложений при появлении attachment (afterResponse), не только в момент ответа ассистента
- [ ] Backfill: клипы со старым `idle` без транскрипта — опционально при list/ensure или разовой команде (не блокирует v1, если все новые save уже auto)
- [x] Config: `LLM_CONTEXT_MAX_CHARS`, лимиты; prompt роутера вынесен в config

### Must not

- [x] Не слать в LLM сырые байты файлов/аудио
- [x] Не ждать ASR внутри ответа ассистента (транскрибация — при save)
- [x] Не всегда подмешивать полный workspace на каждый «привет»
- [x] Не требовать ручной toggle «доступ к данным» в UI v1
- [x] Не строить RAG / tools API в v1
- [x] Не включать записи LiveKit; не отдавать чужие клипы/диалоги
- [x] Не менять контракт люди↔люди сообщений

## UX / UI

- Чат с ассистентом как в 012; без экрана выбора источников
- Library: после Save видно pending транскрипта без обязательного нажатия Transcribe
- Кнопка Transcribe остаётся для повтора / error
- Пробелы в данных — текст бота на русском

## Технические заметки

- `GenerateAiReply`: router call → optional `AssistantWorkspaceContext` → reply call
- Extract: PHP и/или CLI — ADR-007; кэш на `message_attachments`
- ASR: reuse 014; хук в создании `AudioClip`
- Не ломать 015/016
- Frontend: минимальный дифф (library может скрыть/ослабить обязательность кнопки Transcribe для новых клипов)

## Критерии приёмки

1. Save нового клипа → без ручного Transcribe статус уходит в pending и затем done/error (при живом ASR)
2. Вопрос ассистенту без нужды в данных («привет») → ответ без полного workspace (роутер false; проверить по логу/отсутствию огромного context в запросе reply)
3. Запрос сослаться на факт из другого чата → роутер true → ответ опирается на факт
4. Документ txt/pdf/docx в чате → после extract доступен в workspace при релевантном запросе
5. Клип/диалог другого пользователя не утекает
6. Неподдерживаемый mime / клип ещё pending не роняют ответ бота
7. Люди↔люди не вызывают LLM

## Вне скоупа

- UI выбора источников
- RAG, эмбеддинги, tool-calling API
- OCR, xlsx/pptx (следующая итерация)
- Авто-задачи без сообщения пользователя
- Синхронная «догнать все транскрипты» внутри одного ответа ассистента
