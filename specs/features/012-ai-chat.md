# 012 — Чат с ИИ

## Контекст

Локальный сервис `api-llm` уже умеет `POST /api/chat`. Мессенджеру нужен диалог с ИИ у каждого пользователя. См. PDR `012-ai-chat`, ADR-004.

## Цель

У каждого пользователя есть 1:1-чат с системным ассистентом; текст уходит в api-llm, ответ появляется в ленте как обычное сообщение.

## User stories

- Как пользователь, я вижу диалог с ИИ в списке без ручного поиска.
- Как пользователь, я пишу сообщение ассистенту и получаю текстовый ответ.
- Как пользователь, я могу открыть чат с ИИ из диалога «Новый чат».

## Требования

### Must

- [x] Config: `LLM_API_URL`, `LLM_API_TOKEN` (опц.), `LLM_BOT_EMAIL`, `LLM_BOT_NAME`, `LLM_TARGET`, `LLM_TIMEOUT_SEC`
- [x] Seeder создаёт пользователя-бота по `LLM_BOT_EMAIL` (логин в UI запрещён не требуется; пароль случайный)
- [x] При `GET /api/conversations` и после `register` — идемпотентно создаётся 1:1 с ботом, если его ещё нет
- [x] После `POST .../messages` в direct с ботом (отправитель ≠ бот, непустой `body`) — после ответа HTTP ставится генерация ответа
- [x] Клиент `LlmClient` вызывает `POST {LLM_API_URL}/api/chat` с историей диалога (до 20 сообщений)
- [x] Ответ бота — обычный `Message` + broadcast `MessageCreated` **без** `toOthers` (чтобы автор увидел ответ по WS)
- [x] При ошибке LLM — сообщение бота с понятным текстом ошибки (не 500 на send пользователя)
- [x] UI: в «Новый чат» кнопка «Чат с ИИ» (создаёт/открывает диалог с ботом)
- [x] Бот виден в `GET /api/users` (поиск по имени)

### Should

- [x] Системный prompt на русском («ассистент мессенджера»)
- [x] `LLM_DEFAULT_MODEL` / `LLM_TARGET` из env пробрасываются в api-llm

### Must not

- [x] Ответ бота на сообщения без текста (только вложения)
- [x] Бесконечный цикл (бот не триггерит сам себя)
- [x] Группы с автоответом бота в v1
- [x] Стриминг токенов в UI в v1
- [x] Хардкод секретов в репозитории

## UX / UI

- Диалог с ботом выглядит как обычный 1:1 (`peer.name` = имя бота)
- Кнопка «Чат с ИИ» вверху списка поиска в NewChatDialog (режим «Личный»)
- Пока идёт генерация — пользователь ждёт появления сообщения (polling/WS); отдельный индикатор «печатает» не обязателен

## Технические заметки

- Backend: `config/llm.php`, `App\Services\LlmClient`, `App\Services\AiBot`, `App\Jobs\GenerateAiReply`
- Хук в `MessageController::store`
- Env в `.env.example`
- Smoke: `scripts/probe_ai_llm.py`

## Критерии приёмки

1. После seed + login у Alice в списке есть диалог с ассистентом
2. Сообщение Alice в этот диалог → появляется ответ (при работающем api-llm) или текст ошибки
3. Повторный ensure не плодит второй 1:1 с ботом
4. Обычные диалоги люди↔человек не вызывают LLM

## Вне скоупа

- Стриминг, голос, вложения в LLM
- Выбор модели в UI
- Звонки с ботом
