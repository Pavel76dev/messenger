# 004 — Диалоги и сообщения

## Контекст

MVP — личные чаты 1:1 с доставкой через polling.

## Цель

Пользователь находит собеседника, открывает диалог, пишет сообщения и видит новые без перезагрузки (polling).

## User stories

- Как пользователь, я вижу список своих диалогов.
- Как пользователь, я начинаю чат с другим пользователем по поиску.
- Как пользователь, я отправляю текст и вижу его в ленте.
- Как пользователь, я вижу сообщения собеседника через несколько секунд без F5.

## Требования

### Must

- [ ] Миграции: conversations, conversation_user, messages
- [ ] `GET /api/conversations` — список с last message и peer
- [ ] `POST /api/conversations` — `{ user_id }` создаёт или возвращает существующий 1:1
- [ ] `GET /api/users?q=` — поиск других пользователей (не себя)
- [ ] `GET /api/conversations/{id}/messages?after_id=` — история / дельта
- [ ] `POST /api/conversations/{id}/messages` — `{ body }` (непустой текст)
- [ ] Доступ только участникам диалога (403 иначе)
- [ ] Redux: conversations + messages slices
- [ ] UI: список, поиск/старт диалога, лента, отправка
- [ ] Polling активной ленты каждые ~3s с `after_id`

### Should

- [ ] Автоскролл ленты вниз при новых сообщениях
- [ ] Optimistic UI при отправке (опционально; можно ждать ответа API)

### Must not

- [ ] Группы (>2 участников)
- [ ] Пустые сообщения
- [ ] WebSocket

## Критерии приёмки

1. Два пользователя могут переписываться через API + UI
2. Повторный `POST /conversations` с тем же `user_id` не плодит дубликат 1:1
3. Polling подтягивает чужие сообщения
4. Посторонний не читает чужой conversation (403)

## Вне скоупа

- Редактирование / удаление сообщений
- Read receipts, typing indicators
