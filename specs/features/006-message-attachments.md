# 006 — Вложения к сообщениям

## Контекст

В MVP текст-only недостаточно: нужны файлы в переписке (документы, картинки и т.д.).

## Цель

Пользователь прикрепляет несколько файлов к сообщению; собеседник видит их в ленте (превью картинок или ссылка скачивания).

## User stories

- Как пользователь, я выбираю один или несколько файлов и отправляю их с текстом или без.
- Как пользователь, я вижу вложения в ленте: картинки с превью, остальные — ссылкой.
- Как пользователь, я скачиваю вложение по ссылке.

## Требования

### Must

- [ ] `messages.body` nullable; сообщение валидно при непустом body **или** ≥1 файле
- [ ] Таблица `message_attachments`: `message_id`, `path`, `original_name`, `mime`, `size`
- [ ] `POST /api/conversations/{id}/messages` — `multipart/form-data`: `body?`, `files[]` (1–5, каждый ≤ 10 MB)
- [ ] Ответы list/create включают `attachments: [{ id, url, original_name, mime, size }]`
- [ ] Composer: кнопка вложения, список выбранных файлов, отправка FormData
- [ ] Лента: превью image/* , иначе ссылка «Скачать»

### Should

- [ ] Показывать имя и размер выбранных файлов до отправки
- [ ] Ошибка валидации размера/количества на UI

### Must not

- [ ] Редактирование/удаление уже отправленных вложений
- [ ] Preview PDF / антивирус / CDN

## UX / UI

- Composer: иконка скрепки рядом с полем ввода; чипы/список файлов с удалением из выбора
- Пустое body без файлов — кнопка отправки disabled
- В пузыре сообщения: текст (если есть) + блок вложений

## Технические заметки

- Хранение: `attachments/{conversationId}/{uuid}_{safeName}` на диске `public`
- URL: `/storage/...`
- Клиент: FormData; не выставлять JSON Content-Type

## Критерии приёмки

1. Сообщение только с файлами (без текста) создаётся и отображается
2. До 5 файлов на сообщение; 6-й отклоняется валидацией
3. Картинка в ленте кликабельна/открывается; не-картинка — download
4. Посторонний не получает messages чужого диалога (как раньше, 403)

## Вне скоупа

- Голосовые сообщения, сжатие изображений
- Прогресс-бар загрузки больших файлов
