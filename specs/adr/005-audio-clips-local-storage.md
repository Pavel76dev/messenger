# ADR-005: Серверное хранение аудио-клипов

- **Статус:** accepted
- **Дата:** 2026-10-12
- **Контекст:** фича `013-audio-clips` (решение: на сервере, не IndexedDB)

## Контекст

После записи фрагмента пользователь может «сохранить» его без отправки в чат.
Нужна личная библиотека клипов с прослушиванием и удалением.

## Решение

Таблица `audio_clips` (`user_id`, `path`, `mime`, `size`, `duration_ms?`, timestamps).
Файлы на диске `public`: `audio_clips/{userId}/{uuid}.{ext}`.
API только для владельца: `GET/POST /api/audio-clips`, `DELETE /api/audio-clips/{id}`.

Отправка в чат — отдельным шагом через API вложений 006 (`files[]`), не копированием
из библиотеки в v1.

## Альтернативы

1. **IndexedDB** — без sync, пропадает при очистке сайта; отклонено продуктом.
2. **Только как message attachments без библиотеки** — нет «сохранить без отправки».

## Последствия

- Плюсы: клипы доступны с любого браузера того же аккаунта; единый storage с вложениями.
- Минусы / долг: квоты диска; URL на `public` диске по тому же паттерну, что attachments.
