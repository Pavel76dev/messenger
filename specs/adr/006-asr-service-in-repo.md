# ADR-006: ASR внутри messenger (CLI), LLM — снаружи

- **Статус:** accepted
- **Дата:** 2026-10-14
- **Контекст:** фича `014-audio-transcription`

## Контекст

- **LLM** — внешний сервис (`api-llm` по HTTP), так и задумано.
- **Транскрибация** должна быть **внутри приложения**: без отдельного HTTP-демона
  и без облачного ASR.

## Решение

1. Код Whisper лежит в репо: `services/asr/` (faster-whisper, MIT).
2. Laravel Job `TranscribeAudioClip` вызывает **локальный subprocess**:
   `{venv}/python services/asr/cli.py <файл>` → JSON на stdout.
3. Сеть не используется (кроме однократной загрузки весов модели в кэш HF при первом запуске).
4. Отдельный `uvicorn` / `ASR_API_URL` **не нужен** для работы фичи.

## Альтернативы

1. HTTP-микросервис как api-llm — удобно для LLM, для ASR отвергнуто продуктом («должно быть внутри»).
2. Whisper в чистом PHP — нереалистично.
3. Облачный ASR — наружу, платно.

## Последствия

- Плюсы: один деплой-артефакт репо; нет второго всегда-живого порта; тот же Job/pending UX.
- Минусы: на сервере нужен Python venv + ffmpeg рядом с приложением; холодный старт
  модели на каждый CLI-вызов (приемлемо для коротких клипов).
