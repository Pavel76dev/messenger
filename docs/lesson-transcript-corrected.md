## Введение в Git и отслеживание файлов

Давайте еще раз посмотрим на то, чего мы не видим. Я повторю вопрос: какие файлы мы здесь не видим?

Поскольку я не инициализировал Git для нового проекта (его перенесли без Git), мне пришлось сделать это заново. Теперь во вкладке Source Control мы видим все файлы нашего проекта. Их не так уж много.

Я спросил, какие файлы мы не видим, чтобы вы подумали. Есть версии? Вот теперь объясняю: мы не видим файлы, которые указаны в `.gitignore`. Это файл с правилами, которые говорят Git: «Игнорируй, то есть не отслеживай, вот эти файлы».

Что мы там игнорируем?
1. Файл `.env`, который хранит конфиденциальные данные, пароли и ключи от базы данных.
2. Папку `vendor` — PHP-библиотеки Composer.
3. Папку `node_modules` — JavaScript-зависимости npm (это отдельно от `vendor`).

Зачем игнорировать зависимости? Чтобы не переносить тысячи файлов с кодом, написанным до нас. Мы обычно не меняем библиотеки, мы их просто используем, поэтому Git их не отслеживает. Он следит только за нашими файлами: миграциями, сидами и остальным кодом проекта. Зависимости потом ставятся заново: `composer install` и `npm install`.

## Первый коммит

По сути, сейчас у нас есть слепок всего проекта (без игнорируемых папок). Мы его сейчас «закоммитим». Нажимаем кнопку Commit, пишем сообщение, например, «первый коммит». Перед этим нажимаем «Stage All Changes», чтобы включить все изменения. Пока не публикуем.

Теперь, если запустить команду `git log`, мы увидим наш первый коммит и все изменения в нем. Следующие изменения, которые мы сделаем, будут видны здесь же. Это дает большое преимущество в разработке.

## Инструменты разработки с ИИ (Cursor)

Поясню для тех, кто спрашивает. Cursor — это среда разработки, основанная на VS Code, но с интегрированными агентами искусственного интеллекта. Это не отдельная нейросеть, а программа, где ты можешь выбирать разные модели для работы.

Подписка на Cursor:
- Обычная стоит $20 в месяц.
- Есть более дорогая за $60 (я взял ее на месяц вместе с Кириллом). За $20 нам вдвоем хватило на 10 дней работы.

Полностью безлимита нет, потому что для работы моделей требуются дорогие серверы с видеокартами (GPU). Чем больше модель, тем больше ресурсов нужно. Но даже за $20 можно довольно долго программировать.

## Обзор работы агента

Мы дали агенту задачу, и он начал ее выполнять. Он уже:
1. Предложил запустить миграции.
2. Подключил публичную ссылку на файлы командой `php artisan storage:link` (нужна и локально, и на сервере).
3. Создал миграцию, которая:
   - добавляет поле `avatar_path` в таблицу `users` (отдельной таблицы «аватаров» нет);
   - делает `messages.body` nullable (можно отправить только файлы);
   - создаёт таблицу `message_attachments` (вложения к сообщениям).

В `message_attachments` видны поля: `message_id`, `path` (путь к файлу), `original_name`, `mime`, `size`. Поддержка: до 5 файлов на сообщение, до 10 МБ каждый; для картинок в UI — превью.

## Что изменилось в коде

Агент внес изменения в несколько файлов:
- **MessageController**: переработал логику. Раньше ответ собирали «вручную» массивом в нескольких местах; теперь тот же набор полей собирает приватный метод `serialize()` внутри контроллера (это не отдельный класс Serializer). Валидация расширилась: проверяются `body` и загружаемые `files[]` (текст или хотя бы один файл).
- **ProfileController / API**: появились `PATCH /api/me` (имя, email, пароль), `POST /api/me/avatar` и `DELETE /api/me/avatar`.
- **Frontend (React + Redux)**: страница `/profile`, FormData в API-клиенте, обновление composer/ленты сообщений. Frontend через API связывается с Backend (PHP/Laravel).
- **Модели**: `User` с `avatar_url`, `MessageAttachment`, связь `Message::attachments()`.

Вся эта работа с подсветкой изменений (красный — удалено, зеленый — добавлено) видна благодаря системе контроля версий Git.

## Тестирование функционала

Давайте проверим, не обманул ли нас агент.
- **Загрузка фото**: загружаем картинку, меняем пароль и почту — все сохраняется. Перезагружаем страницу — фото пользователя появилось.
- **Отправка файла**: приложили файл к сообщению и отправили. Сообщение пришло (можно и без текста, только с файлами).

Теперь посмотрим в базу данных. Мы видим сообщение и запись о вложении. В таблице указан путь вида `attachments/{id_чата}/{uuid}_имя.ext` и id записи. Если перейти в `public/storage/attachments/...`, мы увидим загруженный файл.

И локально (OpenServer / Windows), и на Linux-сервере для публичного доступа к файлам нужна символическая ссылка:

```bash
php artisan storage:link
```

Она связывает `public/storage` → `storage/app/public`. Без неё URL `/storage/...` в браузере часто не откроется.
